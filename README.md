# Well Forge

Desktop-приложение на Tauri 2 с Vue 3, TypeScript, Vite, Tailwind CSS 4 и shadcn-vue. Интерфейс содержит начальные данные, ручную расстановку скважин и карту результатов. Расчётная модель пока не подключена: в постановке не определена формула штрафа.

## Задача: учет неопределенности запасов при размещении вертикальных газовых скважин

При проектировании разработки газового месторождения запасы углеводородов известны лишь приблизительно. Степень достоверности оценки отражают категории запасов: для разрабатываемых месторождений — А, В1 и В2, для разведуемых — С1 и С2. Если расставить скважины по номинальной оценке, полученная схема может оказаться неудачной при иных фактических запасах. Задача проекта — найти расстановку, сохраняющую приемлемое качество при допустимых отклонениях запасов от оценки.

### Постановка

Залежь представлена двумерной областью из `n` одинаковых квадратных блоков. Требуется разместить `s` вертикальных скважин, где `n > s`. Для каждого блока `j` известна номинальная оценка запасов `Vⱼ`; `Rᵢⱼ` — расстояние между центрами блоков `i` и `j`. Параметр `ε ∈ [0, 1]` задает относительную неопределенность запасов, а `γ ∈ [0, 1]` — экспертную важность расстояния относительно запасов в функции штрафа.

Фактические запасы блока `j` считаются независимой случайной величиной с равномерным распределением на интервале `[Vⱼ(1 − ε), Vⱼ(1 + ε)]`. Выбор `ε` может зависеть от категории запасов.

Бинарная переменная `xᵢⱼ` равна 1, если блок `j` входит в область влияния скважины в блоке `i`, и 0 в противном случае. В частности, `xᵢᵢ = 1` означает размещение скважины в блоке `i`. Допустимая расстановка использует ровно `s` скважин; каждый блок относится к одной области влияния и может быть отнесен только к размещенной скважине:

```text
∑ᵢ xᵢᵢ = s
∑ᵢ xᵢⱼ = 1                 для каждого j
xᵢⱼ ≤ xᵢᵢ                 для всех i, j
xᵢⱼ ∈ {0, 1}
```

При фиксированных запасах вес блока определяется как `λⱼ = Vⱼ / Vₘₐₓ`. Штраф `cᵢⱼ` за включение блока `j` в область влияния скважины `i` учитывает расстояние `Rᵢⱼ`, запасы и параметр `γ`. Базовая задача минимизирует суммарный штраф `F(X) = ∑ᵢ∑ⱼ cᵢⱼ xᵢⱼ` по допустимым расстановкам `X`.

### Учет неопределенности

Из интервалов запасов генерируются `N` сценариев `V⁽¹⁾, …, V⁽ᴺ⁾`. Для каждого сценария `t` рассчитываются веса `λⱼ⁽ᵗ⁾ = Vⱼ⁽ᵗ⁾ / Vₘₐₓ⁽ᵗ⁾`, матрица штрафов `cᵢⱼ⁽ᵗ⁾` и значение целевой функции `F⁽ᵗ⁾(X) = ∑ᵢ∑ⱼ cᵢⱼ⁽ᵗ⁾ xᵢⱼ`. Искомая устойчивая расстановка минимизирует наибольший штраф среди рассмотренных сценариев:

```text
X* ∈ arg minₓ maxₜ F⁽ᵗ⁾(X),
```

где минимум берется по множеству допустимых расстановок.

Предлагаемый способ поиска решения:

1. Сгенерировать `N` независимых реализаций запасов в заданных интервалах.
2. Для каждого сценария `t` найти оптимальную расстановку `X⁽ᵗ⁾` с его матрицей штрафов. При фиксированных местах скважин отдельно решается задача распределения блоков по областям влияния.
3. Оценить каждое найденное решение во всех сценариях: `F(t, u) = F⁽ᵘ⁾(X⁽ᵗ⁾)`. Получится матрица `N × N`, где строка соответствует расстановке, а столбец — сценарию запасов.
4. Выбрать решение с наименьшим максимумом по строке: `t* ∈ arg minₜ maxᵤ F(t, u)`.

Такой перебор выбирает лучшее решение **среди оптимумов отдельных сценариев**; он не гарантирует нахождение глобального минимума по всем допустимым расстановкам. Сравнение штрафов и структуры решений между сценариями позволяет оценить устойчивость выбранной схемы к неопределенности запасов.

Конкретная формула штрафа `cᵢⱼ` в исходной постановке не задана и должна быть уточнена перед реализацией модели.

## Локальный запуск

### Frontend в Docker

Для запуска браузерного dev-сервера без установки Node.js на хосте:

```sh
docker compose up --build
```

Откройте <http://localhost:1420>. Исходники подключены к контейнеру из текущего каталога, поэтому изменения в `src` и других файлах frontend подхватываются Vite без пересборки образа. `node_modules` хранится в отдельном Docker-томе и не смешивается с зависимостями хоста. При следующем запуске достаточно `docker compose up`. После изменения `package.json` или `package-lock.json` остановите dev-сервер, выполните `docker compose run --rm frontend npm ci`, затем снова запустите `docker compose up`.

Этот контейнер запускает только frontend в браузере. Для сборки Linux-приложения используйте отдельный Docker-образ ниже или хостовый запуск.

### Сборка Linux-приложения в Docker

Отдельный образ устанавливает Node.js, Rust и системные зависимости Tauri, собирает приложение и выгружает AppImage в каталог проекта:

```sh
docker build --file Dockerfile.desktop --output type=local,dest=./build/linux .
# или: just docker-build
```

Результат: `build/linux/well-forge.AppImage`. Запуск: `./build/linux/well-forge.AppImage`. AppImage включает библиотеки приложения, в том числе WebKitGTK, поэтому устанавливать `webkit2gtk-4.1` на хосте не требуется. Сборка не требует X11 и не создаёт локальные `node_modules` или `src-tauri/target`. Windows-файл `.exe` по-прежнему собирается в GitHub Actions.

### На хосте

Для запуска без контейнера нужны Node.js, Rust и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/) для вашей ОС.

На CachyOS/Arch установите системные зависимости Tauri:

```sh
sudo pacman -Syu --needed \
  webkit2gtk-4.1 base-devel curl wget file openssl \
  appmenu-gtk-module libappindicator librsvg xdotool
```

```sh
npm ci
just run
```

`just build` собирает desktop-приложение. Для работы только с frontend используйте `just frontend-run` или `just frontend-build`; вторая команда проверяет TypeScript и собирает файлы в `dist`. Список рецептов: `just`.

В верхней панели находятся меню «Файл» и переход в «Параметры». Пункты «Импорт», «Открыть» и «Сохранить» пока недоступны; «Выход» закрывает desktop-приложение. Боковую панель можно свернуть до полоски с иконками; её состояние сохраняется между запусками. В параметрах можно выбрать светлую, тёмную или системную тему. По умолчанию используется системная; выбор сохраняется между запусками.

Основные каталоги frontend: `src/app` — запуск и маршрутизация, `src/components` — общие компоненты, `src/features` — экраны и небольшие примеры, `src/composables` — применение темы, `src/stores` — состояние, `src/lib` — интеграция с Tauri и утилиты, `src/styles` — токены и глобальные стили.

## Сборки GitHub Actions

Workflow [Build desktop app](.github/workflows/build.yml) запускается при отправке любого тега и вручную через **Actions → Build desktop app → Run workflow**. В артефактах завершённого запуска доступны:

- `well-forge-windows-x86_64` — `well-forge.exe`;
- `well-forge-linux-x86_64` — `well-forge-linux-x86_64.tar.gz` с исполняемым файлом `well-forge`.

Linux-сборке нужны установленные GTK 3, WebKitGTK 4.1 и связанные системные библиотеки. После распаковки Linux-архива запустите `./well-forge`.
